# Ethics

## 数据来源原则

OSGE 只能处理以下数据：

- 公开可访问的数据
- 用户自有账号、页面或系统导出的数据
- 获得账号持有人、平台或数据集所有者明确授权的数据
- 许可证允许对应用途的研究数据集

公开可访问不等于可以无限量采集。采集规模、频率和用途仍需符合平台规则、数据许可证和适用法律。

## 许可边界

OSGE 仅允许非商业学习、研究、审计和个人实验用途。

禁止将 OSGE 用于商业采集、商业画像、商业监控、数据转售、获客、风控评分、广告营销、销售情报、竞争情报或其他商业数据服务。

第三方依赖、平台签名资产和参考项目仍适用各自许可证。OSGE 许可证不授予第三方代码、平台服务、账号数据或平台内容的使用权。

## 禁止行为

禁止将 OSGE 用于：

- 绕过登录墙、验证码、限流、权限控制或其他技术访问控制
- 破解接口、滥用私有 API、盗用 session 或冒充他人
- 获取私信、非公开关注列表、非公开评论、私密群组或私密资料
- 自动化骚扰、批量触达、监控或跟踪
- 人肉搜索、身份曝光、羞辱、威胁或定位真实个人
- 构建社工库或隐私数据采集系统
- 无边界递归爬取或高负载采集
- 商业数据采集、商业监控、数据转售或画像服务

## 项目边界

OSGE 用于：

- 网络分析
- 图谱研究
- 公开数据研究
- 关系强度分析
- 数据可视化

OSGE 不用于：

- 商业用途
- 人肉搜索
- 隐私数据采集
- 跟踪或监控
- 骚扰
- 社工库建设
- 未经证据支持的真实身份推断

## Account vs Person

OSGE 默认图节点是 `Account`，不是真实世界中的 `Person`。

系统可以为账号创建 `Identity` 容器，用于内部管理和未来人工确认的跨平台关联。自动创建的身份容器不代表已经识别出真实个人。

只有在证据合法、明确、可追溯并记录置信度时，才可以把多个账号关联为同一个个人或实体。

## 证据要求

关系输出应保留可追溯证据。

至少应记录：

- 来源表或来源文件
- 来源记录 id
- 互动类型
- 时间或时间范围
- 置信度
- 评分解释

## 采集默认值

采集功能应保持保守默认值：

- 一次只处理一个目标账号或一个有边界的查询
- 固定帖子数量上限
- 固定单帖评论数量上限
- 默认不进行递归扩展
- 默认不采集二级评论或保持显式开关
- 默认跳过已知评论和回复
- 记录每条导入数据的来源元信息

## 平台 Adapter 边界

平台 adapter 只用于读取公开可访问、已授权或用户自有的数据。adapter 不应成为绕过访问控制、批量冲击平台或隐藏操作者身份的工具。

实现要求：

- 通过 `adapters/registry.py` 注册平台能力和 UI metadata
- 把平台返回映射为 OSGE 标准记录后再进入 core 层
- 保持采集数量、评论数量和二级评论采集的显式上限
- 对 profile 获取失败、登录状态缺失或平台验证拦截给出明确错误提示
- 不把 cookies、tokens、账号隐私信息、Chromium profile 或原始平台响应写入源码、文档或仓库

本地 Chromium CDP session 仅用于操作者自己的本地授权会话。操作者需要在 Chromium 中自行完成登录或验证。OSGE 不应保存、导出或共享平台 session。

## 数据删除原则

当前 OSGE-collected minimal data 的隐藏和清理操作应优先使用隐藏标记，而不是硬删除。

未来需要补充：

- 按账号删除或隐藏数据的正式流程
- 删除请求记录
- 数据导出与审计记录
- 可复现的数据清理脚本

## 第三方工具和数据集

第三方工具和数据集有各自的许可证、平台规则和使用限制。OSGE 的伦理边界不替代这些规则。

操作者负责确认数据来源、采集方式、存储、分析和分享行为合规。

当前平台 adapter 中存在第三方依赖和参考来源。相关许可、非商业限制和来源关系应在仓库许可文件或第三方声明中记录清楚。
